## 关键概念

- **分治（Divide and Conquer）**：将原问题拆分成若干个规模更小的同类子问题，递归求解每个子问题，再将子问题的解组合成原问题的解。核心三步骤：划分（Divide）、治理（Conquer）、组合（Combine）。
- **归纳法 vs 分治**：归纳法将问题变调为**一个**规模更小的问题；分治将问题拆分为**多个**规模更小的子问题分别求解。
- **合并排序（Merge Sort）**：最经典的分治排序算法。将数组分为两半 → 递归排序前一半 → 递归排序后一半 → 调用有序段合并。时间复杂度 $O(n\log n)$，空间复杂度需要一个辅助数组。
- **合并排序递推式**：$C(n) = 2C(n/2) + (n-1)$（$n > 1$），$C(1) = 0$。其中 $n-1$ 为合并两个各长 $n/2$ 的有序段在最坏情况下的比较次数。展开得 $C(n) = n\log n - n + 1$。
- **递归调用树**：分治算法的递归过程可用二叉树表示。调用顺序为根→左→右（类似于先序遍历），返回顺序为左→右→根（类似于后序遍历）。树深度为 $\log n$ 层。
- **旋转数组**：将有序数组的前 $k$ 个元素整体移到末尾所得到的数组。虽然整体不再有序，但可借助部分有序的性质用分治思想在 $O(\log n)$ 时间内找最大值。
- **分治编写的四步流程**：(1) 判断问题规模是否足够小，若足够小则直接求解；(2) 否则进行划分；(3) 对每个子问题递归调用算法求解；(4) 将各子问题的解组合为原问题的解。
- **划分与组合的难度**：治理（递归调用）通常比较简单；划分与组合才是分治算法设计的核心难点。找到一种有效的划分方式及其匹配的组合方法，分治问题基本就解决了。
- **分治与迭代的关系**：分治算法设计简洁直观，即使产生的递归算法不是最优的，也可以作为跳板进一步启发设计非递归的迭代版本，后者可能在某些常数因子上更优。

## 要点详述

### 一、从归纳法到分治 [00:00–01:24]

此前几章用归纳法来设计算法：将一个问题**变调成**一个规模更小的同类问题来求解 [00:57]。本节课引入另一种设计思路：将一个问题**拆成若干个**比它更小的子问题来解决。这种"拆成若干个小问题来解决"的思路就叫做**分治**（Divide and Conquer）[01:18]。课程正式进入第五章——分治。

教师说明：第四章不额外布置练习；4.5 节（基数排序 / Radix Sort）和 4.6 节（生成排列）因考试时间关系跳过不讲，但基数排序仍然比较重要，建议同学们自行阅读 [01:43–01:57]。

### 二、求最大最小值——分治节省比较次数 [02:03–09:26]

以"在无序数组 $A[1\dots n]$ 中同时求最大值和最小值"为例，对比两种方法。

**朴素方法** [03:23–04:16]：设 $x$ 为最小值、$y$ 为最大值，初始均等于 $A[1]$。遍历剩余元素 $A[2]$ 到 $A[n]$，每次与 $x$ 和 $y$ 分别比较并更新。for 循环执行 $n-1$ 轮，每轮 2 次比较，总计 $2(n-1)$ 次比较。

**分治方法** [04:28–05:44]：将数组从中间切开，递归求出左半段的 min 和 max（记为 $x_1, y_1$）和右半段的 min 和 max（记为 $x_2, y_2$），再取 $\min(x_1, x_2)$ 和 $\max(y_1, y_2)$ 即可。当 $n=2$ 时只需比较 1 次。

递推式分析（设 $n = 2^k$）[05:57–08:56]：

$$C(n) = 2C\left(\frac{n}{2}\right) + 2, \quad C(2) = 1$$

逐层展开（$n = 2^k$）：

$$C(n) = 2C(2^{k-1}) + 2 = 2^2 C(2^{k-2}) + 2^2 + 2 = \cdots = 2^{k-1} C(2) + \sum_{i=1}^{k-1} 2^i$$

由于 $C(2) = 1$ 且 $\sum_{i=1}^{k-1} 2^i = 2^k - 2$，代入得：

$$C(n) = 2^{k-1} + (2^k - 2) = \frac{n}{2} + n - 2 = \frac{3n}{2} - 2$$

朴素方法需要 $2n - 2$ 次比较，分治方法仅需 $3n/2 - 2$ 次，节省约 $n/2$ 次比较 [08:57–09:25]。这说明分治思路即使在直观的问题上也能够带来实际优化。

### 三、二分搜索的分治改写 [09:36–13:33]

二分搜索天然符合分治框架。给定有序数组 $A[low\dots high]$ 和待查元素 $x$：

- 计算 $mid = \lfloor (low + high) / 2\rfloor$
- $A[mid] = x$ → 找到，返回 mid
- $A[mid] > x$ → 递归搜索 $A[low\dots mid-1]$
- $A[mid] < x$ → 递归搜索 $A[mid+1\dots high]$

递归版与 while 循环版完全等价，但递归写法更简洁——它将"继续在左/右半段搜索"的语义直接映射为递归调用自身 [11:37–12:02]。教师指出：将算法思路用汉语写下来，再逐句对应写出代码，正是分治算法设计的典型流程 [13:00–13:26]。最坏情况下时间复杂度与迭代版相同，仍为 $O(\log n)$。

### 四、合并排序——最经典的分治排序 [13:55–18:52]

合并排序的核心逻辑只有三行 [15:47–16:09]：

```
1. 递归对前半段排序
2. 递归对后半段排序
3. 调用有序段合并（merge），将两段合成整体有序
```

关键在于步骤 3：因为步骤 1 和 2 完成后前后两段均已有序，只需调用有序段合并即可。

**递归执行过程** [16:35–18:52]：以 $[8, 4, 3, 1, 6, 2, 9, 7]$ 为例。红色箭头表示递归调用（进入），蓝色箭头表示返回。

- **调用顺序**：根节点 → 左子树 → 左左子树 → … 直到只剩一个元素（无需再分），再递归处理右子树。整体对应树的**先序遍历**（根→左→右）。
- **返回顺序**：左子树返回 → 右子树返回 → 合并当前两段 → 返回到上一层。整体对应树的**后序遍历**（左→右→根）。

这与**自底向上合并排序**的顺序完全不同：自底向上版本是"两两合并 → 四四合并 → 逐层向上"的层次遍历顺序 [18:42–18:52]。

### 五、合并排序的时间复杂度分析 [19:54–24:25]

为简化推导，设 $n = 2^k$。令 $C(n)$ 为规模 $n$ 的数组在最坏情况下的元素比较次数。

**递推式的建立** [20:53–22:14]：

- 递归调用自身两次：$2 \cdot C(n/2)$
- 合并两个各长 $n/2$ 的有序段：最坏情况下一段被完全消耗后另一段还剩一个元素，比较次数为 $n-1$

$$C(n) = 2C\left(\frac{n}{2}\right) + (n-1), \quad C(1) = 0$$

**展开求解** [22:31–23:08]：

$$
\begin{aligned}
C(n) &= 2C\left(\frac{n}{2}\right) + n - 1 \\
&= 2\left[2C\left(\frac{n}{4}\right) + \frac{n}{2} - 1\right] + n - 1 \\
&= 4C\left(\frac{n}{4}\right) + (n-1) + (n-2) \\
&= \cdots \\
&= 2^k C(1) + kn - \sum_{i=1}^k 2^{i-1} \\
&= n\log n - n + 1
\end{aligned}
$$

因此 $C(n) = O(n\log n)$ [23:08]。

**量级角度**：递归树的深度为 $k = \log n$ 层，每层合并的总开销为 $O(n)$（每层所有 merge 操作加起来处理 n 个元素），因此总时间为 $O(n\log n)$。赋值次数（辅助数组的固定拷贝）也是 $O(n\log n)$ [23:44–24:01]。空间复杂度为 $O(n)$，需要与原数组等长的辅助数组。

### 六、分治算法的通用范式 [24:11–29:38]

**三步框架** [26:11–27:45]：

1. **划分（Divide）**：将原问题分解为若干个子问题（二分搜索和合并排序均分成两个）
2. **治理（Conquer）**：对每个子问题，若规模足够小（小于某个阈值）则直接求解，否则递归调用自身
3. **组合（Combine）**：将各子问题的解组合为原问题的解

教师强调：**划分和组合往往是分治算法设计的难点**——找到了有效的划分方法和对应的组合方法，分治问题就基本解决了 [27:36–27:49]。治理过程（递归调用自身）通常比较简单直接。

**编写分治算法时的四步流程** [28:47–29:32]：

1. 先判断问题规模是否足够小（如排序只剩一个元素即有序），若足够小则直接求解
2. 否则进行划分
3. 对每个子问题递归调用算法求解
4. 最后将各子问题的解组合

**分治的优点** [24:35–26:05]：设计简单直观，从思路到代码的映射非常直接。即使分治算法本身不是最优的，它至少为问题提供了一种可行的递归解法，进而可以启发设计更高效的非递归（迭代）算法。

### 七、课堂练习——旋转有序数组找最大值 [30:01–35:29]

**题目** [30:25–32:12]：给定一个包含 $n$ 个互不相同元素的升序数组，经过未知的 $k$ 旋转（将前 $k$ 个元素整体移到末尾），存储在数组 $A$ 中。要求设计一个 $O(\log n)$ 算法求出 $A$ 中的最大元素。旋转量 $k$ 未知。

**示例**：原数组 $[1, 3, 5, 7, 9]$，经 $k=2$ 旋转得 $[5, 7, 9, 1, 3]$，最大值为 $9$。

**分治思路** [33:44–35:07]：

设搜索范围为 $A[low \dots high]$，取 $mid = \lfloor (low + high) / 2\rfloor$：

- **若 $A[low] < A[mid]$**：说明 $A[low \dots mid]$ 这一段是严格升序的（旋转的分界点不在这一段），最大值必然在 $A[mid \dots high]$ 之中 → 递归搜索右半段
- **否则（$A[low] > A[mid]$）**：说明旋转分界点落在左半段中，最大值在 $A[low \dots mid]$ 之中 → 递归搜索左半段

每次比较可将搜索空间压缩约一半，类似于二分搜索，因此时间复杂度为 $O(\log n)$ [35:21]。

教师要求学生在课堂上当场将此算法写成代码并提交（作为随堂练习）。
