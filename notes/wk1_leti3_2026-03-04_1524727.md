## 关键概念

- **确定性 (definiteness)**：算法的每一步必须明确无歧义，但不要求结果唯一（如随机算法）
- **可行性 (feasibility)**：在现有计算资源（算力、带宽、存储、时间）下能以可接受的代价完成任务
- **有穷性 (finiteness)**：执行步骤不会陷入无限循环，能在有限时间内完成
- **最坏情况分析**：衡量算法性能的默认标准——不赌运气，保证在最差输入下仍有可接受的表现
- **二分搜索核心洞察**：有序数据上，一次比较可获知"大于/等于/小于"三种信息，大幅缩小搜索空间

### 算法是什么

算法是让计算机完成特定任务的方法。五个基本特征：
1. **输入**：任务所需的数据（可为空）
2. **输出**：任务产生的结果
3. **确定性**：每步操作明确，计算机看到就知道怎么执行——区别于"加少许盐"这类模糊指令
4. **可行性**：在算力、时间、存储、带宽等约束下可完成——人脸识别要一小时才出结果就不可行
5. **有穷性**：有限步内终止，不陷入死循环

### 评价算法的四个维度

1. **正确性** — 最基本要求，算法必须完成预定任务
2. **易读性** — 设计者和实现者往往不是同一人，算法需能被读懂
3. **健壮性** — 对不同输入、不同场景的适应能力
4. **时间/空间开销** — 本课程分析重点

> 教师强调：分析往往比设计更重要。实际问题中，同一个问题可能有几千种算法，最终哪个胜出，取决于谁的评估分析准确且结果优越。

### 从线性查找到二分搜索

**无序数组查找**：必须遍历每个元素，最坏情况 n 次比较，平均约 n/2 次。最好情况（第一个就命中）对算法评价没有意义。

**有序数组的优势**：将 $A[i]$ 与 $x$ 比较后：
- 若 $A[i] > x$，则 $A[i..n]$ 全部排除
- 若 $A[i] < x$，则 $A[1..i]$ 全部排除
- 一次比较排除的不只是一个元素

**为什么选中间？** 考虑最坏情况。若 $i$ 靠左，运气差时（$A[i] < x$）只能排除很少元素；若 $i$ 靠右同理。只有 $i$ 在中间时，无论 $x$ 在哪一侧，都能排除约一半元素。这是**最坏情况分析指导算法设计**的典型例子。

### 二分搜索伪代码框架

```
low ← 1, high ← n
while low ≤ high:
    mid ← ⌊(low+high)/2⌋
    if A[mid] = x: return mid
    if A[mid] > x: high ← mid-1
    if A[mid] < x: low ← mid+1
return 0
```
