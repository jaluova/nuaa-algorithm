## 关键概念

- **过桥最短路径填表顺序**：$M[i][1]$ 和 $M[i][2]$ 各依赖 $M[i-1][1]$ 和 $M[i-1][2]$（上一行的两个值），因此只能按行从上到下（$i=1 \to n$）计算，一行内的两个值可以先后或同时计算。

- **路径回溯（Path Backtracking）**：在 DP 计算过程中，用辅助数组记录每次 $\min$ 比较的"获胜方"（来自上方还是下方）；计算完所有状态后，从终点出发逆着记录的来源方向回退，即可重构出完整的最优路径。

- **最长公共子序列（Longest Common Subsequence, LCS）**：给定两个序列 $a$ 和 $b$，求它们的公共子序列中最长的那个（可能不唯一，只需求出长度或其中一个即可）。子序列不要求元素在原序列中连续，只要求保持原有顺序。

- **$L[i][j]$ 状态定义**：表示序列 $a$ 的前 $i$ 个元素 $(a_1\cdots a_i)$ 与序列 $b$ 的前 $j$ 个元素 $(b_1\cdots b_j)$ 的最长公共子序列长度。目标为 $L[n][m]$，边界为 $L[i][0]=L[0][j]=0$。

- **LCS 递推关系**：
  $$L[i][j] = \begin{cases}
  L[i-1][j-1] + 1 & \text{if } a_i = b_j \\[4pt]
  \max\Big(L[i-1][j],\ L[i][j-1]\Big) & \text{if } a_i \neq b_j
  \end{cases}$$

- **三个邻居依赖**：计算 $L[i][j]$ 需要左上角 $L[i-1][j-1]$、正上方 $L[i-1][j]$、左方 $L[i][j-1]$ 三个值均已就绪，决定了双重循环的可行性（逐行或逐列均可）。

- **DP 三步法**：教师总结的 DP 设计通用流程——(1) 分析问题最优解结构，定义状态数组；(2) 建立最优解与次优解之间的递推（递归）关系；(3) 根据递推关系中的依赖画出表格，确定从参数最小到最大的计算顺序。

## 要点详述

### 一、过桥最短路径：从画表到编码完成 [00:00]

上节课已给出 $M[i][j]$ 的递推式。本节课从画表分析依赖关系开始 [00:43–01:04]：

已确定：
- $M[1][1] = S[0][1]$，$M[1][2] = S[0][2]$（第一行已知）
- 目标是计算出 $M[n][1]$ 和 $M[n][2]$（最后一行）

教师画出两列 $n$ 行的表 [01:09–01:39]，分析每个 $M[i][j]$ 需要的值是其前一行的两个值——即依赖"上一行"，因此只能**从上到下逐行计算** [02:23–03:37]。

每行内有两个元素，都需要上一行两个值都就绪后才能计算，因此顺序为：先算完第 1 行，再算第 2 行，依此类推。由于只有两列，内层甚至不需要写循环，直接依次写两个赋值语句即可。

**伪代码** [04:10–05:26]：

外层循环 `for i = 2 to n`，内层直接计算：
- $M[i][1] = \min(M[i-1][1] + C[i-1][1] + S[i-1][1],\ M[i-1][2] + C[i-1][2] + S[i-1][3])$
- $M[i][2] = \min(M[i-1][1] + C[i-1][1] + S[i-1][2],\ M[i-1][2] + C[i-1][2] + S[i-1][4])$

循环结束后，最终答案为：
$$\text{minCost} = \min\left(M[n][1] + C[n][1] + S[n][1],\quad M[n][2] + C[n][2] + S[n][2]\right)$$

### 二、路径回溯：辅助数组记录选择 [06:42]

算法求出了最小代价，但还没求出具体是哪条路径。教师提出引入辅助数组 $V$ [07:09–07:52]：

- $V[i][j]$ 记录 $M[i][j]$ 计算时 $\min$ 比较的结果：若选择了来自上方桥（$b_{i-1,1}$）的路径，记"上"（或 1）；若来自下方桥（$b_{i-1,2}$），记"下"（或 0）。
- 整个填表过程顺便把 $V$ 也填满。
- 全部计算完成后，从终点（$i=n$ 处选择的桥）开始，沿着 $V$ 记录的来源方向逆推回去，即可重构出完整的最优路径。

教师指出也可以在 $M$ 全部算完后再逆着推一遍（不额外存 $V$），方法等价 [09:17–09:28]。

### 三、空间优化思路 [10:35]

如果只求最小代价（不求路径），甚至不需要二维数组 $M$：

- 计算每一行只依赖上一行的两个值。
- 用两个变量 $t_1, t_2$ 分别记录上一行的 $M[i-1][1]$ 和 $M[i-1][2]$，一边更新一边滚动，存储开销降至 $O(1)$ [11:44–12:15]。
- 但若要回溯路径，仍需保留更多信息。

### 四、DP 方法论总结与 DP vs 递归 [13:31]

教师总结 DP 设计的"三步法" [13:40–15:01]：

1. **分析最优解的结构**，定义状态数组（如 $M[i][j]$ 的含义）。
2. **建立递推（递归）关系**，描述最优解与次优解之间的依赖——可能涉及加减、比较等操作，不限于简单的加法。
3. **画表确定计算顺序**——从参数最小的子问题开始，逐步推至目标参数。

教师特别强调 [15:25–15:52]：DP 最终写出的算法是**迭代（循环）**形式，而不是递归。虽然分析过程中有递归的思维（大问题化为小问题），但代码实现中用的是表格 + 循环。

### 五、最长公共子序列（LCS）问题的提出 [16:00]

**序列定义** [16:17–16:38]：一组有序排列的元素，允许重复。

**子序列定义** [16:44–17:01]：从原序列中删除若干（0 个或多个）元素后，剩余元素按原有顺序组成的序列。

**子序列总数** [18:10–18:43]：长度为 $n$ 的序列共有 $2^n$ 个子序列（每个元素可选在或不在）。

**LCS 问题** [18:44–19:31]：给定序列 $a$（长度 $n$）和 $b$（长度 $m$），求其最长公共子序列。

**暴力枚举的复杂度** [19:40–21:11]：枚举 $a$ 的所有子序列（$2^n$ 个），逐一检查是否为 $b$ 的子序列——指数级，不可接受。

**目标** [21:17–22:22]：设计一个多项式时间（$O(nm)$）的 DP 算法来求最长公共子序列的长度。

### 六、LCS 的状态定义与目标 [22:45]

沿用 DP 三步法：

1. **定义最优解的结构** [22:45–23:33]：用 $L[i][j]$ 表示序列 $a_1 a_2 \cdots a_i$ 和 $b_1 b_2 \cdots b_j$ 的最长公共子序列**长度**。先求长度，再扩展到求序列本身。

2. **目标值** [23:51–24:17]：$L[n][m]$ 即为所求。当 $i=n, j=m$ 时，$L[n][m]$ 是 $a$ 全序列和 $b$ 全序列的最长公共子序列长度。

3. **边界条件** [24:52–25:40]：当 $i=0$ 或 $j=0$（任一个序列为空），公共子序列必为空，故 $L[i][0] = 0$（对所有 $i$），$L[0][j] = 0$（对所有 $j$）。

### 七、LCS 递推关系推导 [25:58]

考虑 $L[i][j]$ 与更小参数的 $L$ 值之间的关系 [27:06–27:26]：着眼于两个序列的**最后一个元素** $a_i$ 和 $b_j$。

**情形一：$a_i = b_j$** [32:48–34:48]

当 $a_i$ 与 $b_j$ 相等时，这两个元素可以同时出现在最长公共子序列中。可以先将两个序列各去掉最后一个元素，求出 $a_1\cdots a_{i-1}$ 与 $b_1\cdots b_{j-1}$ 的 LCS 长度 $L[i-1][j-1]$，再在末尾加上这个公共元素。因此：

$$L[i][j] = L[i-1][j-1] + 1 \quad (\text{当 } a_i = b_j)$$

**情形二：$a_i \neq b_j$** [27:54–32:43]

当两者不相等时，$a_i$ 和 $b_j$ 不可能同时出现在公共子序列中。因此最长公共子序列要么不包含 $a_i$（而去求 $a_1\cdots a_{i-1}$ 与 $b_1\cdots b_j$ 的 LCS），要么不包含 $b_j$（而去求 $a_1\cdots a_i$ 与 $b_1\cdots b_{j-1}$ 的 LCS）。取两者中较长者：

$$L[i][j] = \max\Big(L[i-1][j],\ L[i][j-1]\Big) \quad (\text{当 } a_i \neq b_j)$$

**递推特征** [34:52–35:19]：与 Fibonacci / 二项式系数的单纯加法不同，LCS 递推引入了条件判断和 $\max$ 比较操作，但仍可机械地在代码中实现。

### 八、二维表格与依赖关系分析 [36:13]

画出 $(n+1) \times (m+1)$ 的二维表 [36:29–37:45]：

- 行号 $i = 0, 1, \dots, n$（对应 $a$ 的前 $i$ 个元素）
- 列号 $j = 0, 1, \dots, m$（对应 $b$ 的前 $j$ 个元素）
- $L[i][j]$ 填入第 $i$ 行第 $j$ 列的格子
- 初始值：第 0 行和第 0 列全为 0
- 目标值：右下角 $L[n][m]$

**依赖关系** [37:55–40:05]：

在计算 $L[i][j]$ 时：
- 若 $a_i = b_j$（相等情形）：只用到了 $L[i-1][j-1]$（**左上角**）
- 若 $a_i \neq b_j$（不等情形）：用到了 $L[i-1][j]$（**正上方**）和 $L[i][j-1]$（**左方**）
- 实际编码时，两种情形都有可能发生，因此三个位置的值都需提前就绪。

**起始位置** [40:06–40:32]：从表中看，唯一三个依赖值都已知的位置是 $L[1][1]$（第 0 行第 0 列已初始化为 0），故从此开始计算。

**遍历顺序** [40:36–41:55]：计算完 $L[1][1]$ 后，只能逐行或逐列推进（不能按对角线走）。因为 $L[1][1]$ 算完后其右方和下方元素的两个依赖（上方/左方）也随之就绪。双重循环方式：`for i = 1..n` 内嵌 `for j = 1..m`，或反过来亦可，结果相同。

### 九、LCS 算法伪代码 [42:22]

```pseudo
声明二维数组 L[0..n][0..m]
// 初始化
for i = 0 to n:  L[i][0] = 0
for j = 0 to m:  L[0][j] = 0
// 填表
for i = 1 to n
    for j = 1 to m
        if a[i] == b[j]
            L[i][j] = L[i-1][j-1] + 1
        else
            L[i][j] = max(L[i-1][j], L[i][j-1])
return L[n][m]
```

**时间复杂度** [46:53–47:01]：双重循环共 $n \times m$ 次迭代，每次 $O(1)$，总时间复杂度 $O(nm)$。

**关键保证** [46:10–46:53]：当计算 $L[i][j]$ 时，$L[i-1][j-1]$、$L[i-1][j]$、$L[i][j-1]$ 这三个参数更小的值必定已经计算完毕——这是由双重循环的遍历顺序保证的。
