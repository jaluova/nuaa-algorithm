## 时间轴

### [00:33] 问题引入

**教学动作**：定义问题。教师先承接上节课，直接给出本节核心问题。

> 给定数组 $A$，已知 $A[p \ldots q]$ 和 $A[q+1 \ldots r]$ 各自内部是**非降序**（升序，允许相等元素）的，两个相邻段之间的大小关系未知。要求合并这两段，使得 $A[p \ldots r]$ 整体有序。

**关键点**：
- 两段连在一起（相邻），不是两个独立数组。
- 内部各自有序，但 $A[q]$ 和 $A[q+1]$ 的大小未知。

### [02:17] 朴素算法：辅助数组法

**教学动作**：提出"如果用辅助数组，思路很简单"，引导学生先找到可行方案。

算法基本思路：
1. 开一个与原数组 $A$ 等大的辅助数组 $B$。
2. 从两段各自取当前最小元素（即两段当前最左端的元素），比较后将更小的放入 $B$。
3. 重复第 2 步，直到其中一段被取完。
4. 将剩余段的元素直接追加到 $B$ 末尾。
5. 将 $B[p \ldots r]$ 整体复制回 $A[p \ldots r]$。

教师强调："如果有一个辅助数组，其实非常简单"——这是建立信心的典型教学策略，先让学生看到可行解。

### [04:48] 循环终止条件分析

**教学动作**：推导循环何时结束。引导学生思考"每次拿走一个元素，经过若干轮必然有一段先空"。

- 每次循环从前段或后段移走一个元素。
- 不会同时取完（因为每次只走一个）。
- 循环结束条件：某一段的元素全部被放入 $B$。

关键结论：**剩余的元素一定比已放入 $B$ 的元素都大**（因为每次都取当前最小的），所以剩余元素可以直接追加。

### [06:24] 算法书写：变量定义

**教学动作**：正式把算法写出来，黑板推导。定义三个核心变量：

| 变量 | 含义 | 初值 |
|------|------|------|
| $s$ | 前半段当前最小元素的下标 | $p$ |
| $t$ | 后半段当前最小元素的下标 | $q+1$ |
| $k$ | 放入辅助数组 $B$ 的位置 | $p$ |

教师特别说明：板书比 PPT 给学生更多思考时间，因此重点内容都写到黑板上。

### [07:11] 算法书写：循环体

**教学动作**：逐行写出 while 循环的逻辑。

```
while (s <= q) and (t <= r):
    if A[s] <= A[t]:
        B[k] = A[s]
        s++
    else:
        B[k] = A[t]
        t++
    k++
```

**教师强调**：每次循环结束 $k$ 必须后移一位，确保下一轮放到正确位置。

### [14:28] 循环条件详解

**教学动作**：回头补全循环条件。先写循环体再写循环条件的"逆序"书写方式，是为了让学生先理解"做什么"再理解"何时停"。

循环条件：$s \leq q$ **且** $t \leq r$

**含义**：
- $s \leq q$：前半段还有元素（$s$ 的定义是前半段当前最小元素的位置，不能超出 $q$）
- $t \leq r$：后半段还有元素

**如果 $s > q$ 或 $t > r$**：对应段的"当前最小元素位置"已经没有意义，不能再做比较。

### [17:08] 循环结束后处理

**教学动作**：处理 while 循环退出的两种情况。

**情况一**：$s > q$（前半段先取完）  
→ 后半段剩余 $A[t \ldots r]$ 直接放入 $B[k \ldots r]$

**情况二**：$t > r$（后半段先取完）  
→ 前半段剩余 $A[s \ldots q]$ 直接放入 $B[k \ldots r]$

最后统一操作：将 $B[p \ldots r]$ 复制回 $A[p \ldots r]$。

教师说明：此时 $k$ 和 $t$（或 $s$）之间的下标关系是可以证明的，但不展开细节。

### [24:18] 正确性分析

**教学动作**：简要分析算法正确性，速度较快（因为算法简单）。

> 每次循环取出当前两段中的最小值放入 $B$，循环结束时剩余元素均不小于已放入值，直接追加即可。最终 $B[p \ldots r]$ 有序，复制回 $A$ 即得正确结果。

教师原话："这个算法很简单，所以正确性分析也比较简洁。"

### [25:43] 开销分析：基本约定

**教学动作**：重申算法分析的计算模型假设（承接上节课规范）。

- **只统计对数组元素的比较和赋值**。
- 下标运算（$s$, $t$, $k$ 的自增、比较）忽略不计。
- 原因：元素可能是复杂对象，而下标一定是简单整数。

### [26:41] 开销分析：比较次数

**教学动作**：分最好/最坏情况讨论。

设前半段有 $n_1$ 个元素，后半段有 $n_2$ 个元素，总元素数 $n = n_1 + n_2$。

| 情况 | 比较次数 | 说明 |
|------|----------|------|
| **最好** | $\min(n_1, n_2)$ | 每次取的都是较短段，最短那段很快取完 |
| **最坏** | $n - 1$ | 交替取元素，只剩一个时停止 |

教师说明：一般关心最坏情况，即比较次数 $\mathbf{O(n)}$ 级别。

### [28:24] 开销分析：赋值次数

**教学动作**：区分赋值次数和比较次数的不同——比较有范围，赋值是固定的。

> 赋值次数 = $\mathbf{2n}$（固定值，无最好最坏差异）

原因：
- 第一步：$A$ 中每个元素被赋值到 $B$ 一次（$n$ 次）
- 最后一步：$B$ 中每个元素复制回 $A$ 一次（$n$ 次）
- 循环内部每次比较伴随一次赋值（已包含在 $n$ 次中）

**观察**：赋值次数（$2n$）明显大于最坏比较次数（$n-1$）。

### [28:24] 开销分析：空间开销

**教学动作**：简短说明。

> 额外空间开销 = **$\mathbf{\Theta(n)}$**（辅助数组 $B$ 与 $A$ 等大）

输入数组 $A$ 本身不计入额外空间开销，只计 $B$。

### [34:47] 第一轮改进：减少不必要的复制

**教学动作**：引导学生思考"这个算法还能改进吗？"。这是重要的教学方法——让学生养成"先找到可行解，再想办法优化"的习惯。

教师原话："大家第一次想到的方法不一定是最优的，经常会先找到一个大概可行的方法，然后进一步去优化。"

**核心观察**（通过示意图分析）：

**情况一**（$s > q$，前半段先取完）：  
- 后半段剩余的元素（黄色区域）在 $A$ 中位置没变，值也没变
- 原算法把它们复制到 $B$ 再复制回 $A$ → 做了两次无意义的复制
- **改进**：这些元素原地不动，只把 $B$ 中已合并好的部分复制回 $A$ 即可

**情况二**（$t > r$，后半段先取完）：  
- 前半段剩余元素需要移到 $A$ 的后半部分
- 原算法：$A$ → $B$ → $A$（两次赋值）
- **改进**：$A[s \ldots q]$ 直接搬到 $A[k \ldots]$（一次赋值），再把 $B[p \ldots k-1]$ 复制回 $A$ 前面

**效果**：显著减少赋值次数，循环体完全不动，只改 while 之后的部分。

### [40:50] 改进后的伪代码

**教学动作**：黑板改写 while 之后的部分。

改进后的后处理逻辑：

```
// 情况一：前半段已取完 (s > q)
将 B[p ... k-1] 复制回 A[p ... k-1]

// 情况二：后半段已取完 (t > r)
将 A[s ... q] 直接搬到 A[k ... ]（从 k 位置开始）
将 B[p ... k-1] 复制回 A[p ... k-1]
```

教师指出：两种情况下 `将 B[p..k-1] 复制回 A[p..k-1]` 这段代码是相同的，可以合并，让代码更简洁。

教师提醒：改进减少了赋值次数，但减少的幅度取决于数据——最坏情况（交替取到只剩一个）减少得很少。

### [46:42] 深层挑战：能否完全不用辅助数组？

**教学动作**：峰回路转，从"减少复制"进一步推进到"完全不用辅助数组"。通过场景讨论引入问题动机。

**动机**：
- 某些场景下**存储空间非常紧张**（教师列举：物联网终端、无人机、嵌入式设备）
- 计算能力可能也很受限
- 需要在计算开销和存储开销之间做平衡

**核心问题**：不引入大小与 $A$ 等同的辅助数组，能否完成两个有序段的**原地合并**？

### [49:22] 从最简单情况入手

**教学动作**：将问题简化。从极端情况开始思考——当后半段只有一个元素时（$r = q+1$）。

> 如果后半段只有一个元素，而前半段 $p \ldots q$ 已经有序，此时合并怎么做？

**教师意图**：先从最简单特例入手，再推广到一般情况。这是在教学生"面对难题时如何切入"的策略。

## 关键概念

| 概念 | 说明 |
|------|------|
| **非降序** | 元素可以相等，$a_1 \leq a_2 \leq \cdots \leq a_n$ |
| **有序段合并 (Merge)** | 给定数组中相邻的两个各自有序的段，合并为整体有序 |
| **辅助数组法** | 引入与原数组等大的额外数组，作为中间存储 |
| **比较次数 (最坏)** | $n-1$ 次（$n = n_1 + n_2$） |
| **赋值次数** | 朴素算法固定 $2n$ 次 |
| **空间开销** | 朴素算法 $\Theta(n)$ |
| **原地合并** | 不使用辅助数组（或只用 $O(1)$ 额外空间）合并两个有序段 |
| **优化策略** | 先有可行解，再分析瓶颈，最后针对优化 |

### 记号约定（与上节课一致）

- 只统计算法中对**数组元素**的比较和赋值操作
- 下标运算（$s, t, k$ 的自增与比较）不计入开销
- 输入数据本身占用的空间不计入额外空间开销

## 要点详述

### 1. 合并两个有序段（Merge）算法

**问题形式化**：  
设数组 $A$ 中有两个相邻段 $A[p \ldots q]$ 和 $A[q+1 \ldots r]$，各自内部满足 $a_i \leq a_{i+1}$。要求重排 $A[p \ldots r]$，使其整体满足非降序。

**朴素算法（带辅助数组）**：

```
Merge(A, p, q, r):
1. s = p, t = q+1, k = p
2. 新建数组 B[1..n]  // n = r-p+1
3. while s <= q and t <= r:
      if A[s] <= A[t]:
          B[k] = A[s]; s++
      else:
          B[k] = A[t]; t++
      k++
4. if s > q:   // 前半段已取完
      将 A[t..r] 复制到 B[k..r]
   else:        // 后半段已取完
      将 A[s..q] 复制到 B[k..r]
5. 将 B[p..r] 复制回 A[p..r]
```

**复杂度**：  
- 比较次数：最坏 $n-1$，最好 $\min(n_1, n_2)$
- 赋值次数：固定 $2n$
- 额外空间：$\Theta(n)$

### 2. 优化版（减少赋值）

**观察**：剩余未移动的元素在 $A$ 中本来就在正确位置上，不需要先搬到 $B$ 再搬回来。

**改进后的后处理**：

```
if s > q:   // 前半段取完，后半段剩余无需移动
    将 B[p..k-1] 复制回 A[p..k-1]
else:       // 后半段取完
    将 A[s..q] 直接搬到 A[k..]  （从下标 k 开始）
    将 B[p..k-1] 复制回 A[p..k-1]
```

**效果**：赋值次数减少（具体减少量取决于数据分布，最坏情况减少很少）。

## 回看建议

1. **掌握 Merge 算法的 while 循环写法**（手写不出错），这是后续归并排序的基础。
