# 算法设计与分析 - 2020年补考试卷 参考答案

## 一、简答题

### (1) 元运算与基本运算

**元运算**：指在计算过程中不能再分解为更小子操作的基本计算步骤。它是算法分析中的最小操作单元。

三种元运算的例子：
- 算术运算：加法、减法、乘法、除法
- 比较运算：两个数值的大小比较
- 赋值运算：将一个值赋给变量

**基本运算**：在解决某类问题的算法中，元运算中的某一个（或某几个）被选为衡量算法效率的核心操作。选择原则是：该操作是算法中最频繁执行的操作，且其执行次数与问题规模 $n$ 之间有明确的数量关系。

基本运算的候选者：
- 排序算法中的**元素比较**（如冒泡排序、快排中比较次数）
- 查找算法中的**元素比较**（如二分查找中与目标值的比较）
- 矩阵运算中的**标量乘法**（如矩阵乘法中的乘法次数）
- 搜索算法中的**节点扩展次数**（如 BFS/DFS 中访问节点数）
- 动态规划中**子问题的计算次数**

### (2) 算法空间的定义

**算法使用空间的定义**：算法在运行过程中临时占用的存储空间大小，包括：
1. 算法本身所占用的存储空间（指令空间）
2. 输入数据所占用的存储空间（输入空间）
3. 算法运行过程中额外分配的辅助空间（辅助空间/工作空间）

**是否包括存储输入的空间**：通常**不包括**。因为输入空间是问题本身给定的，无论使用何种算法都需要存储输入数据。算法分析关注的是算法本身"额外"消耗的资源。但在某些情况下（如原地算法分析），会特别说明是否计入输入空间。

**时间复杂度与空间复杂度的关系**：
- 一般来说，时间与空间可以相互转化——**用空间换时间**或**用时间换空间**。
- 例如：动态规划用表存储子问题解（增加空间）来避免重复计算（减少时间）；而递归回溯只需 $O(\log n)$ 栈空间但可能指数时间。
- 二者没有必然的数学约束关系，但在具体算法设计中经常需要权衡。

### (3) 分治算法与动态规划算法的区别与联系

**联系**：
- 二者都将原问题分解为若干子问题，通过求解子问题来构造原问题的解。
- 都利用了最优子结构性质。

**区别**：

| 维度 | 分治算法 | 动态规划 |
|------|---------|---------|
| 子问题关系 | 子问题相互**独立**，无重叠 | 子问题有**重叠**，被多次使用 |
| 求解方式 | 自顶向下（递归），结果通常不保存 | 自底向上或带备忘录的自顶向下，子问题结果必须保存 |
| 典型例子 | 归并排序、快速排序、二分查找 | 背包问题、LCS、最短路径 |
| 时间效率 | 无重复计算，直接合并 | 通过记忆化避免重复计算 |

## 二、随机算法求 $\sqrt[3]{17}$

### 算法思想

蒙特卡洛方法求积分/求根。注意到 $\sqrt[3]{17}$ 是方程 $x^3 = 17$ 的解，即 $x = \sqrt[3]{17} \approx 2.571$。

构造几何模型：考虑曲线 $y = x^3$ 在区间 $[0, 3]$ 上，函数在 $[x_0, x_1]$ 下的面积。由于 $\text{Randf}()$ 返回 $[0,3]$ 上的均匀随机实数，可以利用均值法：

$$\sqrt[3]{17} = 17^{1/3}$$

但更直接的是：取 $a = \sqrt[3]{17}$ 作为区间 $[2, 3]$ 中的一个点，满足 $a^3 = 17$。

使用随机抛点法：在矩形区域 $[0, 3] \times [0, 27]$ 内随机撒点，统计落入 $y \leq x^3$ 且 $x$ 轴上落在 $[0, a]$ 内的点数比例。

### 另一种（更简洁的均值法）

由于 $17^{1/3}$ 就是函数 $f(x) = x$ 在某种约束下的特值。更实际的方法是使用**牛顿法**的随机化版本，或直接使用**蒙特卡洛积分**求 $\int_0^a x^3 dx = \frac{17}{4} - 0$ 的关系。

### 直接方法（利用 Randf()）

考虑到 $\sqrt[3]{17} = \exp(\frac{1}{3}\ln 17)$，但题目限制使用 `Randf()`，因此应采用随机逼近：

**算法步骤**：
```
Algorithm CubeRoot17(N)
Input: 采样次数 N (越大越精确)
Output: 17 的立方根近似值

1. sum = 0
2. for i = 1 to N:
3.     x = Randf()  // 生成 [0,3] 上均匀随机数
4.     y = 27 * Randf()  // 或直接用 x^3 判断
5.     if y <= 17:  // 点落在 x^3 <= 17 的区域
6.         sum = sum + x
7.         count = count + 1
8. return sum / count  // 条件期望
```

实际上更简单的方法是**期望法**：

考虑 $\sqrt[3]{17}$ 的求值可以转化为：在 $[0, 3]$ 上任取随机数 $X$，计算 $\mathbb{E}[X^3]$。由于均匀分布，$\mathbb{E}[X^3] = \frac{1}{3}\int_0^3 x^3 dx = \frac{1}{3} \cdot \frac{81}{4} = 6.75$。

所以如果我们不是求期望，而是要求 $a = \sqrt[3]{17}$，即 $a^3=17$。在 $[0,3]$ 上均匀采样，若 $x^3 \leq 17$ 的点比例为 $p = a/3$，故 $a = 3p$。

**最终算法**：
```
Algorithm CubeRoot17(N)
1. count = 0
2. for i = 1 to N:
3.     x = Randf()
4.     if x^3 <= 17:
5.         count++
6. p = count / N
7. return 3 * p  // 近似值约为 2.571
```

**正确性**：当 $N$ 足够大时，统计比例 $p$ 依概率收敛于真实比例 $a/3$（大数定律），其中 $a = \sqrt[3]{17}$。

## 三、快速排序 QUICKSORT

### (1) 算法思想

快速排序采用分治策略：
1. **划分**：从数组中选择一个"主元"（pivot），将数组划分为两部分——左侧所有元素 $\leq$ 主元，右侧所有元素 $\geq$ 主元。
2. **递归**：对左右两个子数组递归执行同样的划分操作。
3. **合并**：由于划分后主元已处于最终位置，左右子数组排序后整个数组自然有序，无需显式合并。

### (2) 补充伪代码

```
过程 quicksort(A, low, high)
1. if low < high then
2.     w = split(A, low, high)  // 划分, w 为主元最终位置
3.     quicksort(A, low, w - 1)  // 递归排序左半
4.     quicksort(A, w + 1, high)  // 递归排序右半
5. end if
```

### (3) 最坏情况分析

**最坏情况**：每次划分后，主元都恰好是当前子数组的最小值或最大值，导致划分极不均衡——一边有 $n-1$ 个元素，另一边为 0。

**何时发生**：
- 输入数组已经有序（升序或降序），且每次选取第一个（或最后一个）元素作为主元。
- 例如：输入 $A = [1, 2, 3, 4, 5]$，每次取首元素作主元，划分后左边为空，右边为 $n-1$ 个元素。

**最坏情况比较次数**：
$$C(n) = C(n-1) + C(0) + (n-1) = C(n-1) + (n-1)$$

其中 $(n-1)$ 是划分过程中与主元的比较次数。展开得：
$$C(n) = (n-1) + (n-2) + \cdots + 1 = \frac{n(n-1)}{2} = \Theta(n^2)$$

**结论**：最坏情况下 QUICKSORT 的时间复杂度为 $O(n^2)$。

### (4) 改进方法

**随机化快排**：每次随机选取主元，而非固定选取第一个或最后一个元素。

**分析**：随机选取主元时，期望比较次数满足：
$$T(n) = \frac{1}{n}\sum_{k=1}^{n} [T(k-1) + T(n-k)] + (n-1)$$

解得 $T(n) = O(n\log n)$（期望时间复杂度）。

虽然最坏情况仍可能发生（概率极小，约为 $2^{-n}$），但期望性能显著改善。此外，也可采用"三数取中"策略（取首、中、尾三个元素的中位数作为主元），进一步优化。

## 四、求最小的 $k$ 个元素

### (1) 算法设计与注释

**算法思想**：使用快速选择（Quickselect）找出第 $k$ 小的元素，然后遍历数组找出所有 $\leq$ 该值的 $k$ 个元素，再排序输出。

由于 $k = \Theta(n/\log n)$，直接排序 $O(n\log n)$ 不满足要求。使用线性时间选择算法。

```
Algorithm FindSmallestK(A[1..n], k)
Input: 无序数组 A, k
Output: B[1..k] 升序排列

// 步骤1: 找到第k小的元素
1. pivot = Select(A, 1, n, k)  // 线性时间选择, O(n)

// 步骤2: 收集所有 <= pivot 的元素
2. j = 1
3. count = 0
4. for i = 1 to n:
5.     if A[i] <= pivot and count < k:
6.         B[j] = A[i]
7.         j++
8.         count++

// 步骤3: 对B排序 (k个元素)
9. sort(B[1..k])  // O(k log k)

10. return B
```

`Select(A, low, high, k)` 函数实现中位数的中位数算法（BFPRT 算法）：
- 分组取中位数
- 递归求中位数的中位数
- 以此作主元划分
- 最坏情况线性时间

### (2) 时间复杂度证明

- 步骤1（Select 找第 $k$ 小元素）：最坏情况 $O(n)$（BFPRT 算法保证）
- 步骤2（收集元素）：$O(n)$（遍历一次）
- 步骤3（排序 $k$ 个元素）：$O(k\log k) = O((n/\log n) \cdot \log(n/\log n)) = O(n)$

因为 $k\log k = \Theta(\frac{n}{\log n} \cdot \log n) = \Theta(n)$。

故总时间复杂度为 $\Theta(n)$，满足要求。

## 五、动态规划求组合数 $C_n^m$

### (1) 递推关系式

组合数的递推公式（杨辉三角/Pascal 公式）：
$$C_n^m = C_{n-1}^{m-1} + C_{n-1}^m$$

边界条件：
$$C_n^0 = C_n^n = 1 \quad (n \geq 0)$$

### (2) 数据结构与初始条件

**数据结构**：使用二维数组 `C[0..n][0..m]` 存储子问题的解。其中 `C[i][j]` 表示 $C_i^j$（从 $i$ 个元素中选 $j$ 个的组合数）。

**初始条件**：
- `C[i][0] = 1`（对所有 $i$，选 0 个只有一种方式）
- `C[i][i] = 1`（对所有 $i$，全选只有一种方式）
- `C[i][j] = 0`（当 $j > i$ 时，无意义）

### (3) 伪代码

```
Algorithm CombinationDP(n, m)
Input: n, m (0 <= m <= n)
Output: C_n^m

1. 创建二维数组 C[0..n][0..m], 初始化为 0
2. for i = 0 to n:
3.     C[i][0] = 1  // 选0个
4.     for j = 1 to min(i, m):
5.         if j == i:
6.             C[i][j] = 1
7.         else:
8.             C[i][j] = C[i-1][j-1] + C[i-1][j]
9. return C[n][m]
```

### (4) 复杂度分析

- **时间复杂度**：双重循环，外层 $n+1$ 次，内层最多 $m$ 次，总复杂度 $\Theta(n \cdot m)$。最坏情况（$m \approx n/2$）为 $\Theta(n^2)$。
- **空间复杂度**：DP 表大小为 $\Theta(n \cdot m)$。若只需最终结果，可优化为 $O(m)$（只保留上一行）。

## 六、卡片交换问题

### 分析

初始状态：卡片呈**降序排列**，即 $n, n-1, \dots, 2, 1$。

操作规则：可以交换**相隔一张**的任意两张卡片。即可以交换位置 $i$ 和 $i+2$ 的卡片（中间恰好有一张）。

目标：变为升序排列 $1, 2, \dots, n$。

**可行性分析**：
- 一次交换（间隔一张）改变位置的奇偶性：位置 $i$ 和 $i+2$ 的奇偶性相同（同为奇数或同为偶数）。
- 因此，奇数位置上的卡片只能在奇数位置之间移动，偶数位置同理。
- 初始降序序列中，奇数位置和偶数位置分别按各自的规则排列。

对任意 $n$，分析：
- $n=3$：$[3, 2, 1]$，可以交换位置 1 和 3（交换 $3$ 和 $1$），得到 $[1, 2, 3]$，可行，只需 1 次。
- $n=4$：位置 1 和 3 同奇偶，位置 2 和 4 同奇偶。$4$ 在位置 1，$1$ 在位置 4——奇偶性不同，无法直接交换。需要证明一般情况。

实际上，当 $n \leq 3$ 时存在解；当 $n > 3$ 时，只有当奇数/偶数位置内部可以自行排序时才可行。这等价于：奇数位集合 $\{1,3,5,\dots\}$ 上的元素可以通过相邻间隔交换进行任意排列——但这仅当集合大小为 1 或可通过冒泡实现。实际上这等价于奇偶位置上的"冒泡排序"。

**结论**：对于任意 $n$，该问题总是有解的。因为间隔一张交换等价于在奇/偶子序列上的冒泡排序。

### 算法设计

**最小的交换次数**：等价于计算奇数位置子序列和偶数位置子序列各自的逆序数之和。

由于初始是完全降序，最小的交换次数 = 奇数位逆序数 + 偶数位逆序数。

设 $n_{odd}$ 为奇数位置的数量，$n_{even}$ 为偶数位置的数量。
- 奇数位置上的元素集为 $\{n, n-2, n-4, \dots\}$（从大到小）
- 它们在奇数位置上需要变成升序，逆序数为 $\binom{n_{odd}}{2}$

交换次数 = $\binom{n_{odd}}{2} + \binom{n_{even}}{2}$

其中 $n_{odd} = \lceil n/2 \rceil$，$n_{even} = \lfloor n/2 \rfloor$。
