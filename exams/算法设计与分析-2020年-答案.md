## 第一题

假设 $f_0=f_1=1$，$f_i = f_{i-1} + f_{i-2}\ (i>1)$。

### (1) 设计 $O(\log n)$ 算法计算 $f_n$

**算法思想**：使用矩阵快速幂。斐波那契数列可表示为矩阵形式：

$$\begin{bmatrix} f_n \\ f_{n-1} \end{bmatrix} = \begin{bmatrix} 1 & 1 \\ 1 & 0 \end{bmatrix} \begin{bmatrix} f_{n-1} \\ f_{n-2} \end{bmatrix}$$

递推可得：

$$\begin{bmatrix} f_n \\ f_{n-1} \end{bmatrix} = \begin{bmatrix} 1 & 1 \\ 1 & 0 \end{bmatrix}^{n-1} \begin{bmatrix} f_1 \\ f_0 \end{bmatrix} = \begin{bmatrix} 1 & 1 \\ 1 & 0 \end{bmatrix}^{n-1} \begin{bmatrix} 1 \\ 1 \end{bmatrix}$$

利用矩阵快速幂（二分幂），可在 $O(\log n)$ 时间内求得矩阵的 $n-1$ 次幂。

**伪代码**：

```
Algorithm Fibonacci(n)
Input: 正整数 n
Output: f_n

1. if n == 0 or n == 1 then return 1
2. 定义矩阵 M = [[1, 1], [1, 0]]
3. result = MatrixPower(M, n-1)  // 计算 M^(n-1)
4. return result[0][0] + result[0][1]  // f_n = result * [f_1, f_0]^T

Algorithm MatrixPower(M, k)
Input: 矩阵 M, 幂次 k
Output: M^k

1. 初始化 res 为单位矩阵 I = [[1, 0], [0, 1]]
2. base = M
3. while k > 0:
4.     if k & 1:  // k 的二进制最低位为 1
5.         res = res * base  // 矩阵乘法, 2×2 矩阵相乘共需 8 次整数乘法
6.     base = base * base
7.     k = k >> 1
8. return res
```


### (2) 时间复杂度证明

矩阵规模固定为 $2 \times 2$，每次矩阵乘法需要 $2^3=8$ 次整数乘法和若干次加法，为常数时间 $O(1)$。

`MatrixPower` 采用二分求幂，while 循环执行 $\lceil\log_2 k\rceil$ 次，其中 $k=n-1$。

每次循环最多执行 2 次矩阵乘法（当 `k & 1` 为真时 `res = res * base`，以及必然执行的 `base = base * base`）。每次矩阵乘法为 $O(1)$。

故总时间复杂度为 $O(\log n)$。整个过程只使用整数运算，不涉及浮点数。

## 第二题

### P 类问题

**定义**：存在多项式时间确定型算法求解的判定问题集合。即对于问题规模为 $n$ 的实例，存在算法能在 $O(n^k)$（$k$ 为常数）时间内给出是/否的正确答案。

**例子**：最短路径问题（判定版本）——给定图 $G$ 和值 $k$，是否存在从 $s$ 到 $t$ 长度不超过 $k$ 的路径。Dijkstra 算法即可在多项式时间内求解。

### NP 问题

**定义**：存在多项式时间非确定型算法求解的判定问题集合。等价地说，给定一个"证书"（猜测的解），可以在多项式时间内验证其正确性的问题集合。

**例子**：旅行商问题（TSP）的判定版本——给定 $n$ 个城市及其两两距离，问是否存在总距离不超过 $B$ 的哈密顿回路。虽然我们不知道如何在多项式时间内求解，但给定一条回路，可以在多项式时间内验证其总距离是否 $\leq B$。

### NP 完全问题（NPC）

**定义**：满足以下两个条件的判定问题：
1. 该问题属于 NP；
2. 所有 NP 问题都可以多项式时间归约到该问题（即 NP-hard）。

**例子**：布尔可满足性问题（SAT）、旅行商问题（TSP）、图的着色问题、子集和问题等。

### 三者关系

$$\text{P} \subseteq \text{NP}, \quad \text{NPC} \subseteq \text{NP}$$

- P 一定是 NP（确定型算法本身就是一种非确定型算法），但 NP 是否等于 P 是计算机科学中尚未解决的千禧年难题（P vs NP 问题）。
- NPC 是 NP 中"最难"的一类问题：如果任意一个 NPC 问题存在多项式时间算法，则所有 NP 问题都存在多项式时间算法，即 P = NP。
- NPC 问题同时也是 NP-hard 问题。但 NP-hard 问题不一定属于 NP（如停机问题是 NP-hard 但不是 NP）。

用集合关系表示：

$$\text{P} \subseteq \text{NP}, \quad \text{NPC} = \text{NP} \cap \text{NP-hard}, \quad \text{NPC} \subseteq \text{NPH}$$

## 第三题

### (1) 直接算法伪代码

```
Algorithm FindMinMax(A[1..n])
Input: 整数数组 A[1..n], n 是 2 的整数幂
Output: 最小值 min 和最大值 max

1. min = A[1], max = A[1]
2. for i = 2 to n:
3.     if A[i] > max then max = A[i]
4.     if A[i] < min then min = A[i]
5. return (min, max)
```

### (2) 元素比较总次数

循环共执行 $n-1$ 次。每次迭代进行两次比较（比 max 和比 min）。

比较总次数 = $2(n-1)$。

### (3) 分治递归改进算法

**算法思想**：将数组递归地分成两半，分别找出左半部分和右半部分的最小值和最大值，然后比较左半部分的 min 与右半部分的 min 得到全局 min，类似地得到全局 max。直到子问题规模为 1 或 2（当 $n=1$ 时，min=max=A[1]；当 $n=2$ 时，一次比较即可确定 min 和 max）。

**伪代码**：
```
Algorithm FindMinMaxDC(A, low, high)
Input: 数组 A, 左边界 low, 右边界 high
Output: (min_val, max_val)

1. if low == high:  // 只有一个元素
2.     return (A[low], A[low])
3. if low + 1 == high:  // 两个元素
4.     if A[low] < A[high]:
5.         return (A[low], A[high])
6.     else:
7.         return (A[high], A[low])
8. mid = (low + high) / 2
9. (minL, maxL) = FindMinMaxDC(A, low, mid)
10. (minR, maxR) = FindMinMaxDC(A, mid+1, high)
11. return (min(minL, minR), max(maxL, maxR))
```

### (4) 分治策略比较次数分析

设 $C(n)$ 为规模为 $n$ 时所需的比较次数。

当 $n=1$ 时，$C(1)=0$（不需要比较）。
当 $n=2$ 时，$C(2)=1$（一次比较即可）。
当 $n>2$ 时：$C(n) = 2C(n/2) + 2$（分别递归求解两个子问题各 $C(n/2)$ 次，然后比较两个 min 和两个 max 各需 1 次比较）。

解得：
$$C(n) = 3n/2 - 2$$

比直接算法的 $2(n-1)$ 更优。例如：
- $n=2$：直接算法 $2$ 次，分治 $1$ 次
- $n=1024$：直接算法 $2046$ 次，分治 $1534$ 次

## 第五题

### 算法思路

这是一个贪心算法问题（类似"救生艇"问题）：

1. 将所有人的体重从小到大排序。
2. 使用双指针技术：最轻的人（`left`）和最重的人（`right`）。
3. 如果最轻的人和最重的人的体重之和 $\leq limit$，则两人同乘一艘船（`left++`, `right--`）。
4. 否则最重的人单独乘一艘船（`right--`）。
5. 每次安排一艘船，计数 `ans++`。
6. 当 `left > right` 时结束。

### 伪代码

```
Algorithm MinRescueBoats(people[], n, limit)
Input: people[1..n] 体重数组, limit 最大承重
Output: 最少船只数

1. sort(people[1..n])  // 升序排序
2. left = 1, right = n, ans = 0
3. while left <= right:
4.     if left == right:
5.         ans = ans + 1
6.         break
7.     if people[left] + people[right] <= limit:
8.         left = left + 1
9.         right = right - 1
10.    else:
11.        right = right - 1
12.    ans = ans + 1
13. return ans
```

### 复杂度分析

- **时间复杂度**：排序需 $O(n\log n)$，双指针遍历需 $O(n)$。总时间复杂度为 $O(n\log n)$。
- **空间复杂度**：仅需常数个辅助变量，$O(1)$（不计输入数组）。

## 第六题

### 算法思路

使用回溯（DFS）枚举所有可能的抛掷次序。

状态表示：`dfs(step, coins, seq, z_remain, f_remain)`
- `step`：当前是第几次抛掷（1~17）
- `coins`：当前手中的金币数
- `seq`：当前的抛掷序列字符串
- `z_remain`：剩余的正面次数
- `f_remain`：剩余的反面次数

约束条件：
1. 总正面次数为 6，总反面次数为 11（但第 17 次必须是反面），所以在递归 16 次时，正面 6 次，反面 10 次。
2. 最后一掷（第 17 次）为反面，结束时金币为 0。所以在第 16 步结束时金币数必须为 1（因为反面朝上减 1 后为 0）。
3. 过程中金币数必须非负。

### 伪代码

```
Algorithm CoinTossSequences()
Output: 所有可能的抛掷次序方案数

1. ans = []  // 存放所有符合条件的序列
2. // 前16次: 6次正面(A), 10次反面(B)
3. dfs(1, 3, "", 6, 10)
4. return ans.size()  // 方案数

Function dfs(step, coins, seq, z_remain, f_remain):
    // 剪枝: 金币不能为负
    if coins < 0:
        return
    // 到达第17步 (前16次已完成)
    if step == 17:
        // 最后一步为反面朝上后, 金币刚好为0
        if coins - 1 == 0:
            ans.append(seq + "B")
        return
    // 尝试正面
    if z_remain > 0:
        dfs(step + 1, coins * 2, seq + "A", z_remain - 1, f_remain)
    // 尝试反面
    if f_remain > 0:
        dfs(step + 1, coins - 1, seq + "B", z_remain, f_remain - 1)
```
