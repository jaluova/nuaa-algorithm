# 排序算法性能测试与分析

## 实验目的

本实验围绕五种经典排序算法展开：插入排序、选择排序、冒泡排序、自底向上归并排序、堆排序。实验目标如下：

1. 通过编码实现五种排序算法，加深对不同排序思想的理解。
2. 通过随机数据集上的实际运行结果，观察不同时间复杂度算法的性能差异。
3. 将理论复杂度与实验结果进行对照，理解 $O(n^2)$ 与 $O(n log n)$ 在数据规模扩大时的实际影响。
4. 分析不同算法的空间复杂度与常数开销，理解“理论最优”和“实际表现”之间的联系。

## 实验方法

本次实验实现了以下五种排序算法：

| 算法 | 时间复杂度 | 空间复杂度 |
|------|------------|------------|
| 插入排序 | $O(n^2)$ | $O(1)$ |
| 选择排序 | $O(n^2)$ | $O(1)$ |
| 冒泡排序 | $O(n^2)$ | $O(1)$ |
| 自底向上归并排序 | $O(n log n)$ | $O(n)$ |
| 堆排序 | $O(n log n)$ | $O(1)$ |

其中，自底向上归并排序采用非递归方式实现，并使用辅助数组完成合并；堆排序使用大顶堆原地排序。

为了保证实验结果具有可比性，本实验采用以下策略：

1. 对每个数据规模先生成一份原始随机数组。
2. 每个算法都对同一份原始数组的副本进行排序，确保输入完全一致。
3. 使用固定随机种子 $20260403$，保证实验结果可复现。
4. 排序结束后使用 `std::is_sorted` 检查结果是否为非降序，避免计时结果建立在错误排序上。

## 数据集与系统配置

### 数据集

实验数据为随机生成的整数数组，整数范围为 $[1, 10^9]$。测试规模如下：$1000$、$10000$、$50000$、$100000$，这些规模能够较明显地反映平方级排序算法和线性对数级排序算法在性能上的差距。

### 系统配置

- 操作系统：`Darwin 23.4.0 (arm64)`
- 处理器架构：`Apple Silicon / arm64`
- 编译器：`Apple clang version 15.0.0`
- 编译参数：`-std=c++17 -O2 -Wall -Wextra -pedantic`

### 结果分析

1. 从整体结果看，实验数据与理论复杂度高度一致。插入排序、选择排序和冒泡排序都属于 $O(n^2)$，当数据规模从 $1000$ 增加到 $100000$ 时，耗时增长十分明显；而自底向上归并排序和堆排序属于 $O(n log n)$，即使在最大规模下仍然能在很短时间内完成。
2. 在 $100000$ 规模下，归并排序耗时为 $4.197 ms$，堆排序耗时为 $8.144 ms$，而插入排序达到 $1599.404 ms$，选择排序和冒泡排序分别达到 $9525.802 ms$ 和 $9904.351 ms$。这说明当规模增大后，复杂度差异会直接转化为巨大的运行时间差距。
3. 在本次实验中，归并排序始终是速度最快的算法之一，并且在 $10000$、$50000$、$100000$ 三个较大规模下都明显快于堆排序。这说明虽然二者同为 $O(n log n)$，但归并排序在本实验环境中的常数因子更有优势。
4. 堆排序虽然速度略慢于归并排序，但它仍远快于三种平方级排序，并且只需要 $O(1)$ 的额外空间，因此在“效率”和“空间占用”之间体现出较好的平衡，也是课堂中重点强调它的重要原因。
5. 三种 $O(n^2)$ 算法之间也存在明显差别。在 $100000$ 规模下，插入排序约为 $1.6$ 秒，明显快于选择排序和冒泡排序的约 $9.5$ 到 $9.9$ 秒；这表明同一复杂度等级下，不同算法的内部操作方式和常数开销也会影响实际表现。

## 实验感想

通过这次实验，我对“算法复杂度”不再只是停留在公式层面的理解，而是看到了它在真实程序运行中的直接体现。在小规模数据下，不同算法都可以较快完成任务，但随着数据规模增大，$O(n^2)$ 与 $O(n log n)$ 的差距会迅速放大。这说明在实际问题中，算法选择比单纯优化代码细节更重要。

同时，我也进一步理解了时间复杂度和空间复杂度之间的平衡关系。归并排序速度快、表现稳定，但需要额外空间；堆排序则在保持较优时间复杂度的同时具备原地排序优势。通过亲自实现并测试这些算法，我对课堂中讲到的复杂度分析有了更加具体和深入的认识。
