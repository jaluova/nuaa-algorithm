## 二、算法的基本概念

### 2.1 算法的五个特征

| 特征 | 含义 |
|------|------|
| **输入** | 任务所需的数据（可为空） |
| **输出** | 任务产生的结果 |
| **确定性** | 每步操作明确无歧义 |
| **可行性** | 在资源约束下可完成 |
| **有穷性** | 有限步内终止 |

### 2.2 评价算法的四个维度

1. **正确性** — 最基本要求
2. **易读性** — 便于他人理解实现
3. **健壮性** — 对不同输入的适应能力
4. **时间/空间开销** — 本课程分析重点

> 分析往往比设计更重要。同一问题可能有几千种算法，最终哪个胜出，取决于谁的评估分析准确且结果优越。

### 2.3 分析约定

在分析数组类算法时，**只计算对元素的操作（比较、赋值、运算），对下标的任何操作一律忽略不计**。输入数据本身占用的空间不计入额外空间开销。

## 三、二分搜索

### 3.1 从线性查找到二分搜索

**无序数组查找**：必须遍历每个元素，最坏情况 $n$ 次比较，平均约 $n/2$ 次。最好情况（第一个就命中）对算法评价没有意义。

**有序数组的优势**：将 $A[i]$ 与 $x$ 比较后：
- 若 $A[i] > x$，则 $A[i..n]$ 全部排除
- 若 $A[i] < x$，则 $A[1..i]$ 全部排除
- 一次比较排除的不只是一个元素，而是一半

**为什么选中间？** 考虑最坏情况。若选靠左的元素，运气差时（$A[i] < x$）只能排除很少元素。只有选中间，无论 $x$ 在哪一侧，都能排除约一半元素。这是**最坏情况分析指导算法设计**的典型例子。

### 3.2 算法伪代码

```
low ← 1, high ← n
while low ≤ high:
    mid ← ⌊(low + high) / 2⌋
    if A[mid] = x: return mid
    if A[mid] > x: high ← mid - 1
    if A[mid] < x: low ← mid + 1
return 0
```

### 3.3 正确性证明

**情况1：$x$ 不存在于数组中**
- `A[mid] = x` 永远不会触发
- 每次循环必然压缩搜索空间
- 最终 `low > high`，循环退出，返回 0

**情况2：$x$ 存在于数组中**
- 搜索空间压缩时，永远不会把 $x$ 所在位置排除在外
- 搜索空间不断缩小，$x$ 始终在待搜索区间内
- 最差情况下搜索空间只剩一个元素时，下一轮必然命中

### 3.4 最坏情况时间复杂度推导

这是本节核心内容。

**第1轮后剩余元素**：无论 $n$ 奇偶，最坏情况下剩余 $\lfloor n/2 \rfloor$ 个。

**关键引理**：$\lfloor\lfloor n/2\rfloor/2\rfloor = \lfloor n/4\rfloor$

用二进制视角理解：除以 2 = 右移一位，向下取整 = 截断低位。连续两次操作等价于直接右移两位。

**通项**：$j$ 轮循环后，最坏情况下剩余 $\lfloor n / 2^j \rfloor$ 个元素。

**建立不等式**：设最坏情况需要 $j$ 轮，则第 $j-1$ 轮后只剩 1 个元素：

$$1 \le \frac{n}{2^{\,j-1}} < 2 \quad\Rightarrow\quad 2^{\,j-1} \le n < 2^{\,j}$$

取对数（本课程 $\log$ 默认底数为 2）：

$$j - 1 \le \log n < j \quad\Rightarrow\quad j = \lfloor\log_2 n\rfloor + 1$$

**结论**：最坏情况下二分搜索的元素比较次数为 $\lfloor\log n\rfloor + 1$。

## 四、合并两个有序段

### 4.1 问题定义

给定数组 $A$，已知 $A[p..q]$ 和 $A[q+1..r]$ 各自内部是非降序的，两个相邻段之间的大小关系未知。要求合并这两段，使得 $A[p..r]$ 整体有序。

### 4.2 辅助数组法

```
Merge(A, p, q, r):
    s ← p, t ← q+1, k ← p
    新建辅助数组 B
    while s ≤ q and t ≤ r:
        if A[s] ≤ A[t]:
            B[k] ← A[s]; s++
        else:
            B[k] ← A[t]; t++
        k++
    if s > q: 将 A[t..r] 复制到 B[k..r]
    else:     将 A[s..q] 复制到 B[k..r]
    将 B[p..r] 复制回 A[p..r]
```

**复杂度**：

| 指标 | 最好 | 最坏 |
|------|------|------|
| 比较次数 | $\min(n_1, n_2)$ | $n-1$ |
| 赋值次数 | $2n$（固定） | $2n$（固定） |
| 额外空间 | $\Theta(n)$ | $\Theta(n)$ |

### 4.3 优化：减少不必要的复制

**观察**：剩余未移动的元素在 $A$ 中本来就在正确位置上，不需要先搬到 $B$ 再搬回来。

- 前半段先取完：后半段剩余元素原地不动，只把 $B$ 中已合并好的部分复制回 $A$
- 后半段先取完：前半段剩余元素直接搬到 $A[k..]$，再把 $B$ 中已合并好的部分复制回 $A$

**效果**：显著减少赋值次数，但减少幅度取决于数据分布。

## 五、插入排序

### 5.1 从无辅助空间合并到插入排序

**问题**：能否不使用辅助数组完成两个有序段的合并？

**最简单情形**：后半段只有一个元素 $x = A[q+1]$，前半段 $A[p..q]$ 已有序。

```
s ← q
while s ≥ p and A[s] > x:
    A[s+1] ← A[s]
    s ← s - 1
A[s+1] ← x
```

**极端情况验证**：
- $x$ 最大：while 不进入，$x$ 留在原位 ✓
- $x$ 最小：while 遍历全部，退出后 `A[s+1]` 即 `A[p]` 处放入 $x$ ✓

**推广到多元素**：外层再加一层循环，每次将 $A[i]$ 插入前面有序段。

```
for i ← q+1 to r:
    x ← A[i]
    s ← i - 1
    while s ≥ p and A[s] > x:
        A[s+1] ← A[s]
        s ← s - 1
    A[s+1] ← x
```

### 5.2 关键洞察：后半段有序性未被利用

回顾算法逻辑：每次只取一个元素与前面有序段比较并插入。**即使 $A[q+1..r]$ 是无序的，算法仍然正确**——后半段本身的顺序不影响最终结果。

### 5.3 从合并到插入排序

任何一个数组 $A[1..n]$ 可以看作：
- $A[1]$ 单独一个元素，自然有序
- $A[2..n]$ 为"后半段"

调用上述算法（$p=1, q=1, r=n$），每次将无序段的第一个元素插入到前面的有序段中，这就是**插入排序**。

### 5.4 复杂度分析

| $i$ | 最坏比较 | 最坏赋值 |
|-----|---------|---------|
| 2 | 1 | 2 |
| 3 | 2 | 3 |
| ... | ... | ... |
| $n$ | $n-1$ | $n$ |

**比较次数**：$1 + 2 + \cdots + (n-1) = \frac{n(n-1)}{2} = \Theta(n^2)$

**赋值次数**：比比较次数多约 $(n-1)$ 次，也是 $\Theta(n^2)$

**空间复杂度**：$O(1)$（仅一个辅助变量 $x$）

### 5.5 时间-空间权衡

| 方案 | 时间 | 额外空间 |
|------|------|----------|
| 辅助数组合并 | $O(n)$ | $\Theta(n)$ |
| 无辅助合并（插入） | $O(n^2)$ | $O(1)$ |

用时间换空间的典型案例。
